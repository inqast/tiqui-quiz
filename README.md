# Tiqui Quiz

Tiqui Quiz превращает текстовый **шаблон** в короткий интерактивный курс. Родителю или педагогу не нужны редактор кода, сервер, npm или знания программирования: конструктор работает локально в браузере и упаковывает курс вместе с медиа.

## Как пользоваться

Откройте **[Tiqui Quiz в браузере](https://inqast.github.io/tiqui-quiz/)** в актуальном настольном браузере на базе Chromium. Создайте или импортируйте шаблон, заполните локальными файлами медиаслоты и скачайте архив для ученика.

### Шаблон и проект `.tiqui`

Шаблон — это текст курса. Его можно ввести в редакторе, импортировать из `.md` или получить с помощью мастера промпта. В шаблоне медиаслот задаёт место, вид и обязательное описание медиа; сам файл в текст не встраивается.

Чтобы продолжить редактирование позднее, нажмите «Сохранить проект». Файл `.tiqui` — редактируемый ZIP-проект с `project.json`, `lesson.md` и каталогом `media/`. Открывайте его кнопкой «Открыть проект». Не переименовывайте и не изменяйте файлы внутри архива вручную.

Медиаслот без выбранного файла остаётся видимым в конструкторе, но скачать ученический квиз нельзя, пока не заполнены все слоты. Удалите ненужный слот или выберите файл.

### Локальные медиа

В теме и в отдельном вопросе может быть по одному медиаматериалу; вводное медиа темы и медиа вопроса могут использоваться одновременно. Поддерживаются только локальные файлы:

- JPEG, PNG или WebP — до 15 МБ;
- MP3 или M4A — до 50 МБ;
- MP4 с H.264/AAC — до 250 МБ;
- суммарно все медиа проекта — до 250 МиБ (262 144 000 байт).

Для каждого медиа обязательно укажите понятное описание. Для изображения оно используется как альтернативный текст, а для аудио и видео — как доступное название элемента. Медиа суммарным объёмом больше 125 МиБ заметно увеличивают потребление памяти и время упаковки; перед ученическим экспортом конструктор запросит подтверждение. Во время импорта, сохранения и экспорта редактор и медиапанель временно заблокированы; операцию можно отменить.

Проект допускает до 1000 медиафайлов. Размер шаблона, manifest и готового ученического HTML ограничен 2 МиБ каждый (UTF-8). Зарезервированные системные имена слотов (`con`, `prn`, `aux`, `nul`, `clock$`, `com1`–`com9`, `lpt1`–`lpt9`) не допускаются.

### Создание шаблона с помощью ИИ

Кнопка «Создать с помощью ИИ» открывает локальный мастер промпта. По умолчанию он создаёт обычный шаблон без медиа. Включите опцию медиа, если нейросеть должна расставить медиаслоты, затем выберите размещение, частоту и допустимые виды. Нейросеть создаёт только текстовые слоты: локальные файлы выберите самостоятельно в конструкторе.

Скопируйте сформированный запрос в DeepSeek, ChatGPT, Claude или другой чат. Tiqui Quiz не подключается к нейросетям и ничего им не отправляет автоматически. Если сервис вернул шаблон в блоке кода, используйте кнопку копирования блока, а не визуально оформленный текст.

### Архив для ученика и автономный запуск

Кнопка «Скачать квиз для ученика» всегда создаёт ZIP, даже если в курсе нет медиа. Архив содержит `index.html` и, при наличии медиа, каталог `media/`; исходный шаблон и manifest в него не входят.

Перед передачей ученику:

1. Полностью распакуйте ZIP в отдельную папку.
2. Оставьте `index.html` и `media/` вместе, сохранив их имена и структуру.
3. Откройте `index.html` двойным щелчком в актуальном настольном Chromium-браузере.
4. Не удаляйте архив проекта `.tiqui`, если планируете редактировать курс.

После распаковки квиз и медиа работают через `file://` без интернета. Официальная гарантия v1 относится к актуальным desktop-браузерам на базе Chromium. Microsoft Edge проверяется ручным smoke-тестом, но отдельная автоматическая матрица для него не запускается. Firefox, Safari и мобильные браузеры не входят в гарантируемый сценарий.

Правильные ответы исключены из очевидных исходных файлов ученического архива, однако полноценной криптографической защиты или обфускации ответов в v1 нет.

### Если что-то не работает

- «Файл не выбран»: заполните каждый медиаслот либо удалите ненужный слот.
- Медиа не проигрывается: проверьте формат и кодеки, полностью распакуйте ZIP и убедитесь, что `media/` лежит рядом с `index.html`.
- Проект не открывается: используйте исходный `.tiqui`; не меняйте его содержимое и расширение вручную.
- Архив создаётся медленно: сократите число или размер файлов; проекты свыше 125 МиБ требуют подтверждения.
- При проблеме в другом браузере повторите сценарий в актуальном Chrome или другом desktop Chromium.

Кнопка «Очистить редактор» удаляет текущий шаблон после подтверждения. На телефонах интерфейс может отображаться адаптивно, но мобильное создание и прохождение курсов пока не поддерживается официально.

## Приватность

Tiqui Quiz не собирает и не отправляет содержимое шаблона, проекта или локальных медиа. Разбор, проверка, предпросмотр и упаковка выполняются в текущей вкладке. При использовании GitHub Pages хостинг передаёт браузеру только приложение; выбранные пользователем файлы не загружаются на сервер. Распакованный ученический квиз работает полностью без сети.

## Безопасность

Проект автоматически проверяет зависимости, анализирует JavaScript с помощью CodeQL и выполняет браузерные сценарии с потенциально вредоносным шаблоном. Опубликованная версия дополнительно сканируется OWASP ZAP после развёртывания и раз в неделю.

Если вы обнаружили уязвимость, не создавайте публичный Issue. Используйте инструкции для приватного сообщения в [`SECURITY.md`](./SECURITY.md).

## Формат документа

Документ начинается с названия курса. `Иконка`, `Описание` и `ID` необязательны. Стабильный `ID` полезен: по нему готовый квиз отличает свой сохранённый прогресс от других курсов.

Если `Иконка` отсутствует или оставлена пустой, используется стандартная иконка: `🧩` для курса и `📘` для темы.

```md
# Великие географические открытия

Иконка: 🗺️
Описание: Один урок — несколько минут
ID: geography-discoveries
```

Темы обозначаются заголовком второго уровня:

```md
## Морской путь в Индию

Иконка: 🧭
```

Вопрос начинается с заголовка третьего уровня. Поддерживаются пять типов.

### Выбор

Ровно один вариант отмечается `[x]`. Комментарий варианта необязателен и показывается только после проверки.

```md
### Выбор

Зачем европейцы искали морской путь в Индию?

- [x] За пряностями и дорогими товарами
  Подсказка: Верно: пряности в Европе стоили очень дорого.
- [ ] Чтобы найти Северный полюс
  Подсказка: Экспедиции шли вдоль Африки на юг.

Объяснение: Сухопутная торговля с Азией стала сложной и дорогой.
```

### Правда или ложь

```md
### Правда или ложь

Колумб понял, что открыл новую часть света.

Ответ: ложь
Если правда: Колумб до конца жизни считал новые земли Азией.
Если ложь: Верно — он был уверен, что добрался до Индии.
Объяснение: Поэтому местных жителей европейцы назвали индейцами.
```

Допустимые значения ответа: `правда`, `ложь`, `true`, `false`, `да`, `нет`.

### Ввод

Несколько допустимых ответов разделяются вертикальной чертой `|`. Регистр букв и повторные пробелы при проверке не учитываются. Небольшая опечатка засчитывается, но квиз показывает правильное написание.

```md
### Ввод

В каком году Колумб доплыл до Америки?

Ответы: 1492
Подсказка: Вспомни конец XV века.
Объяснение: Землю увидели 12 октября 1492 года.
```

### Порядок

Пункты записываются сразу в правильном порядке.

```md
### Порядок

Расставь события по порядку:

1. Колумб просит у королей корабли
2. Корабли выходят из Испании
3. Экспедиция пересекает океан
4. Моряки видят землю

Объяснение: Экспедиция вышла из Испании в августе 1492 года.
```

### Пары

Левая и правая части разделяются символами `=>`.

```md
### Пары

Соедини путешественника и открытие:

- Колумб => Америка
- Васко да Гама => Морской путь в Индию
- Беллинсгаузен и Лазарев => Антарктида
```

## Общие правила

- Не вставляйте HTML или JavaScript: они будут показаны как обычный текст.
- У каждой темы должен быть хотя бы один вопрос.
- У вопроса должны быть формулировка и данные, необходимые его типу.
- `Подсказка` и `Объяснение` необязательны и появляются только после проверки.
- Порядок тем в документе сохраняется. Вопросы внутри темы перемешиваются при каждом прохождении.
- Ошибочный вопрос возвращается в конец очереди, чтобы ребёнок попробовал снова.
- В выборе должен быть ровно один правильный вариант; одинаковые варианты запрещены.
- В вопросе «Правда или ложь» поле `Ответ` указывается ровно один раз.
- Пустые и повторяющиеся варианты в `Ответы` для свободного ввода автоматически удаляются.
- Элементы порядка не должны повторяться; сами номера могут идти не по порядку, поскольку важен порядок строк.
- Каждая пара должна содержать ровно один `=>`; левые и правые части разных пар не должны повторяться.

Можно передать нейросети этот файл и попросить: «Создай курс по приложенному материалу в формате Tiqui Quiz. Разбей материал на темы по 6–10 коротких вопросов, используй разные типы вопросов и добавь понятное объяснение к каждому сложному ответу».

## Разработка и тесты

Для использования конструктора Node.js не нужен. Он требуется только разработчикам для автоматических тестов.

Исходный код находится в `src/`:

- `parser.js` — разбор и проверка Markdown;
- `player.js` — проигрыватель курса и его стили;
- `app.js` — интерфейс конструктора и экспорт;
- `quiz.template.html` — HTML-оболочка конструктора.

Файл `quiz.html` генерируется из этих исходников и остаётся автономным пользовательским приложением. Не редактируйте его вручную: после изменений в `src/` выполните:

```bash
make build
```

Команда `make check-build` проверяет, что закоммиченный `quiz.html` соответствует исходникам. Эта проверка также входит в `make test`.

Первоначальная настройка:

```bash
make install
```

Запуск всех проверок:

```bash
make test
```

Отдельные наборы:

```bash
make test-unit
make test-browser
make test-browser-ui
```

Полный цикл сохранения, открытия и ученического экспорта при лимите 250 МиБ проверяется отдельно: `TIQUI_MEDIA_PERF=1 npm run test:media-performance`. Проверка сохраняет старый проект до завершения импорта, учитывает SHA-256, выходные архивы, отклик интерфейса и RSS браузера. Прежний целевой лимит 500 МиБ не прошёл этот сценарий и снижен.

`make help` выводит полный список целей. Соответствующие npm-команды также остаются доступны напрямую.

Модульные тесты напрямую импортируют Markdown-парсер из `src/parser.js`. Браузерные тесты запускают Chromium, загружают файл курса, проходят все пять типов вопросов и открывают экспортированный автономный HTML. Тестовые браузеры хранятся локально в `.playwright-browsers` и не попадают в репозиторий.

## GitHub Actions

Workflow `.github/workflows/tests.yml` запускается при каждом push и pull request. Unit- и браузерные тесты выполняются независимыми jobs. Unit job также проверяет, что `quiz.html` пересобран после изменений в `src/`; при падении браузерных тестов GitHub сохраняет Playwright-артефакты на семь дней.

После первого запуска рекомендуется сделать проверки `Unit tests` и `Browser tests` обязательными в настройках защиты основной ветки GitHub.

Workflow `.github/workflows/deploy-pages.yml` запускается после успешного завершения `Tests` для ветки `main`. Он забирает именно проверенный commit, повторно проверяет актуальность сборки и публикует `quiz.html` как главную страницу GitHub Pages. Перед первым запуском выберите `GitHub Actions` в `Settings → Pages → Build and deployment → Source`.
