# Безопасность

## Как сообщить об уязвимости

Не создавайте публичный GitHub Issue, если проблема позволяет выполнить чужой код, раскрыть данные или нарушить работу опубликованного приложения.

Используйте один из приватных каналов:

- создайте приватный отчёт через вкладку **Security → Advisories → Report a vulnerability** в GitHub;
- напишите на [inqast@gmail.com](mailto:inqast@gmail.com?subject=Tiqui%20Quiz%3A%20уязвимость).

Укажите шаги воспроизведения, браузер и минимальный пример Markdown. Не прикладывайте персональные данные ребёнка, настоящие учебные материалы с конфиденциальной информацией, токены или пароли.

Мы постараемся подтвердить получение сообщения в течение семи дней. Пожалуйста, не публикуйте детали до исправления проблемы.

## Автоматические проверки

При push и pull request выполняются:

- unit- и браузерные тесты, включая сценарии с вредоносным Markdown;
- проверка известных уязвимостей npm-зависимостей;
- статический анализ CodeQL;
- проверка новых зависимостей в pull request.

После публикации и раз в неделю GitHub Actions запускает пассивное сканирование веб-версии с помощью OWASP ZAP. Его предупреждения собираются в отчёт и первоначально не блокируют публикацию, поскольку часть HTTP-заголовков управляется GitHub Pages.
